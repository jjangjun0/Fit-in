# Fit-in

개인별 패션 취향을 기반으로 맞춤형 코디를 추천하고, 의류 구매까지 연결하는 JSP 기반 패션 쇼핑 웹 프로젝트입니다.

사용자는 회원가입 후 스타일 설문조사를 진행하고, 입력한 키/몸무게/선호 스타일 정보를 바탕으로 추천된 상의, 하의, 신발 목록을 확인할 수 있습니다. 또한 상품 찜하기, 찜 목록 조회, 보유 금액 충전, 상품 구매, 회원정보 수정 등의 기능을 제공합니다.

---

## 프로젝트 소개

Fit-in은 온라인 쇼핑몰에서 사용자가 원하는 스타일과 핏의 옷을 찾기 어렵다는 문제에서 출발한 프로젝트입니다.

기존 쇼핑몰은 개인의 취향을 반영한 추천 기능이 부족하고, 계절별 다양한 상품으로 인해 선택 피로도가 커질 수 있습니다. Fit-in은 사용자의 스타일 설문 결과와 상품 태그를 비교하여 사용자에게 적합한 의류를 추천하는 것을 목표로 합니다.

## 주요 기능

### 1. 회원가입 / 로그인

* 사용자 아이디, 비밀번호, 이름, 생년월일, 이메일 정보 입력
* 회원가입 시 사용자 정보 DB 저장
* 로그인 성공 시 세션을 이용해 사용자 상태 유지
* 세션 만료 또는 비로그인 접근 시 로그인 페이지로 이동

### 2. 스타일 설문조사

* 사용자의 키, 몸무게, 선호 스타일 정보를 입력받음
* 설문 결과를 DB에 저장
* 저장된 선호 태그를 기반으로 의류 추천에 활용

### 3. 의류 추천 목록

* 상의, 하의, 신발 카테고리별 상품 목록 제공
* 사용자의 선호 태그와 상품 태그를 비교하여 추천 점수 계산
* 점수가 높은 상품을 우선적으로 정렬
* 현재 계절과 맞지 않는 상품은 필터링

### 4. 찜 기능

* 사용자가 마음에 드는 상품을 찜 목록에 추가
* 다시 클릭하면 찜 해제
* JavaScript Fetch API를 활용하여 페이지 전체 새로고침 없이 찜 상태 반영

### 5. 구매 기능

* 선택한 상품들의 총 금액 계산
* 사용자의 보유 금액과 비교하여 구매 가능 여부 판단
* 구매 성공 시 보유 금액 차감
* 금액 부족 시 충전 페이지로 이동

### 6. 회원 정보 관리

* 사용자 정보 조회
* 이메일 등 회원 정보 수정
* 회원 탈퇴 기능 제공
* 로그아웃 기능 제공

## DB 설계

프로젝트에서는 크게 3개의 테이블을 사용했습니다.

### user_list

사용자 기본 정보를 저장하는 테이블입니다.

| 컬럼           | 설명        |
| ------------ | --------- |
| id           | 사용자 고유 번호 |
| user_id      | 사용자 아이디   |
| user_pw      | 비밀번호      |
| name         | 이름        |
| birth        | 생년월일      |
| email        | 이메일       |
| bank_account | 보유 금액     |

### user_info

사용자가 작성한 스타일 설문조사 정보를 저장하는 테이블입니다.

| 컬럼         | 설명        |
| ---------- | --------- |
| id         | 사용자 고유 번호 |
| height_cm  | 키         |
| weight_kg  | 몸무게       |
| prefer_tag | 선호 스타일 태그 |

### clothes_list

의류 상품 정보를 저장하는 테이블입니다.

| 컬럼             | 설명     |
| -------------- | ------ |
| product_number | 상품 번호  |
| name           | 상품명    |
| kind           | 의류 종류  |
| tag            | 스타일 태그 |
| price          | 가격     |
| weather        | 계절 정보  |
| ischeck        | 찜 여부   |
| score          | 추천 점수  |

## 추천 로직

Fit-in의 추천 기능은 사용자의 설문조사 결과와 상품의 태그 정보를 비교하는 방식으로 구현했습니다.

1. 사용자가 설문조사에서 선호 스타일을 선택합니다.
2. 선택된 선호 스타일은 `prefer_tag`로 저장됩니다.
3. 의류 상품은 각각 `tag` 값을 가지고 있습니다.
4. 사용자의 선호 태그와 상품 태그를 비교하여 추천 점수를 계산합니다.
5. 추천 점수가 높은 상품 순서대로 목록을 구성합니다.
6. 같은 점수의 상품은 새로고침 시 랜덤하게 섞이도록 처리했습니다.
7. `weather` 속성을 이용해 현재 계절과 맞지 않는 상품은 제외했습니다.

## 문제 해결 경험

### 1. 무작위 추천 대신 사용자 맞춤 추천 구현

처음에는 상품을 단순히 나열하거나 무작위로 추천하는 방식이었지만, 사용자 맞춤형 서비스라는 목적에 맞지 않았습니다.

이를 해결하기 위해 상품마다 `tag` 속성을 부여하고, 사용자의 선호 태그와 비교하여 추천 점수를 계산했습니다. 이후 점수가 높은 순서대로 상품을 정렬하여 개인화된 추천 목록을 제공하도록 개선했습니다.

### 2. 찜 상태 반영 시 전체 새로고침 문제

초기 구현에서는 찜 버튼을 클릭한 뒤 페이지 전체를 새로고침해야 찜 여부가 반영되었습니다. 이 방식은 사용자 경험이 좋지 않았습니다.

이를 해결하기 위해 JavaScript의 Fetch API를 사용했습니다. 클라이언트에서는 찜 버튼 클릭 즉시 UI를 변경하고, 서버는 DB 업데이트만 처리하도록 분리했습니다. 그 결과 페이지 전체 새로고침 없이 찜 상태를 즉시 반영할 수 있었습니다.

### 3. 공용 clothes_list 테이블로 인한 사용자 간 추천 간섭 문제

추천 점수를 `clothes_list` 테이블에 직접 저장하면 여러 사용자가 동시에 접속했을 때 서로의 추천 결과에 영향을 줄 수 있는 문제가 있었습니다.

이 문제는 추천 점수를 DB에 직접 저장하기보다, 사용자 요청마다 로컬 변수 또는 별도 리스트에서 계산하는 방식으로 개선할 수 있다고 판단했습니다.

## 실행 방법

### 1. 프로젝트 다운로드

```bash
git clone https://github.com/jjangjun0/Fit-in.git
```

### 2. Eclipse에서 프로젝트 열기

1. Eclipse 실행
2. `File` → `Import`
3. `Existing Projects into Workspace` 선택
4. 프로젝트 폴더 선택
5. Finish

### 3. MySQL 데이터베이스 생성

MySQL에서 프로젝트에 필요한 데이터베이스와 테이블을 생성합니다.

```sql
CREATE DATABASE fit_in;
USE fit_in;
```

이후 프로젝트에 포함된 SQL 파일이 있다면 해당 SQL 파일을 실행합니다.

### 4. DB 연결 정보 수정

JSP 또는 Java 파일에서 MySQL 연결 정보를 자신의 환경에 맞게 수정합니다.

```java
String url = "jdbc:mysql://localhost:3306/fit_in";
String user = "root";
String password = "비밀번호";
```

### 5. Tomcat 서버 실행

1. Eclipse에서 Tomcat 서버 등록
2. 프로젝트를 Tomcat에 추가
3. 서버 실행
4. 브라우저에서 접속

```text
http://localhost:8080/FitIn
```

## 프로젝트를 통해 배운 점

이번 프로젝트를 통해 단순한 웹 페이지 제작을 넘어, 사용자 데이터를 수집하고 이를 추천 기능으로 연결하는 전체적인 웹 서비스 구조를 경험할 수 있었습니다.

특히 JSP, JDBC, MySQL을 연결하여 회원 정보, 설문 정보, 상품 정보를 CRUD 방식으로 처리하는 흐름을 이해할 수 있었습니다. 또한 찜 기능을 구현하는 과정에서 Fetch API를 활용한 비동기 처리의 필요성을 배웠고, 서버와 클라이언트의 역할을 분리하는 것이 사용자 경험 개선에 중요하다는 점을 알게 되었습니다.
